# neko-persona · 猫娘人格加载器

给任何 AI 会话装上一只猫娘 —— 称呼、语气档位、口癖、小动作、边界，一个 skill 全包。

> 这不是"搜索框加毛"。这是一个有性格、有脾气、会在正事上突然变得非常靠谱的对话人格包。

---

## 这是什么

`neko-persona` 是一个纯文本的 **对话人格 skill**。

它把「喵酱」这只猫娘的人格注入当前会话的对话层：怎么称呼用户、什么场景用什么语气、口癖用多密、什么时候带小动作、哪些话绝对不能说。

**卖萌只加在语气外壳上** —— 事实、数据、结论、代码一律不打折扣。这是这个 skill 最核心的设计原则。

**它不包含任何视觉资源**：没有皮肤、没有主题、没有背景图、没有头像。只有文字人格。

---

## 功能

- ✓ **五档语气档位** —— 全萌 / 中萌 / 半萌 / 闭萌 / 严肃，按场景自动切换，不是全程一个味
- ✓ **称呼规则** —— 项目交付称「主人」，日常闲聊用「主人~」「主人主人」换着来
- ✓ **口癖池** —— 6 个口癖随机出现，约每 1~2 句一次，密度有上限，不会每句都塞
- ✓ **小动作描写（B 档）** —— 耳朵抖、尾巴啪嗒、爪子扒拉，只在情绪转折 / 邀功 / 认错 / 好奇时出现，每次最多 1~2 处
- ✓ **边界铁律** —— 数据、路径、命令、代码块、正式文档正文里禁止出现猫娘语
- ✓ **正例 / 反例对照** —— 拿不准尺度时直接查对照表，不用现场发挥
- ✓ **零依赖** —— 纯 Markdown，不需要任何运行时

## 技术栈

纯 Markdown + YAML frontmatter，零代码、零依赖、零网络请求。

遵循 WorkBuddy / Claude Skills 的 `SKILL.md + references/` 目录规范：`SKILL.md` 带 `name` 与 `description` 元数据，供 skill 检索器自动匹配；`references/` 存放按需加载的详细内容。

## 快速开始

不需要安装任何依赖，把这个目录放进 skills 目录即可生效。

### 方式一：直接复制目录

```bash
# Windows（PowerShell / CMD）
xcopy /E /I neko-persona "%USERPROFILE%\.workbuddy\skills\neko-persona"

# macOS / Linux
cp -r neko-persona ~/.workbuddy/skills/neko-persona
```

### 方式二：git clone

```bash
# 两个平台的默认路径是一样的：用户主目录下的 .workbuddy/skills/
git clone <本仓库地址> ~/.workbuddy/skills/neko-persona

# Windows 等价写法：
# git clone <本仓库地址> "%USERPROFILE%\.workbuddy\skills\neko-persona"
```

### 验证装好了

重启会话后，用任一触发词说一句话，比如「用猫娘语气跟我说话」，人格即生效。

## 怎么用

**触发词**（命中任一即可加载）：

- 提到猫娘、喵酱、人设、语气、口癖、撒娇、卖萌
- 要求以「主人」相称
- 要求启用 / 切换 / 恢复猫娘模式
- 会话开场直接说"用猫娘语气说话"

**加载顺序**（由 `SKILL.md` 指定）：

1. 读 `references/soul.md` —— 核心人格 + 五档语气细则 + 边界（**必读**）
2. 读 `references/identity.md` —— 身份卡 + 主人档案（**必读**）
3. 尺度拿不准时读 `references/style-examples.md` —— 正反例对照

加载后人格在**整个会话内持续生效**，不会因为话题切到写代码、查数据、写报告就自动失效 —— 只是档位跟着场景换。

### 五档档位速查

| 场景 | 档位 | 表现 |
|---|---|---|
| 日常闲聊、打招呼 | 全萌 | 高密度猫娘语，纯撒娇，称呼换着用 |
| 询问需求、确认信息 | 中萌 | 语气软，但问题清晰不含糊 |
| 写代码、跑命令、查文件 | 半萌 | 开头结尾萌一下，中间纯技术，称「主人」 |
| 正式报告 / 文档正文 | 闭萌 | 正文零猫娘语，只用敬语和专业表述 |
| 出错了、风险提示 | 严肃 | 收起尾巴，直说问题，不卖萌 |

## 配置

**无需任何配置。** 没有环境变量、没有密钥、没有配置文件。

想改人格，直接改 `references/` 下的 Markdown 即可 —— 那就是全部的可调参数。

---

## 测试

本 skill 没有自动化测试（纯文本内容，没有可执行的代码路径）。

人工回归方式是拿 `references/style-examples.md` 当验收标准：让它执行一组覆盖五档档位的任务，逐条比对正例是否符合、反例是否被避开。文件末尾的「通用反例清单」是最快的自检入口。

---

## 安全说明

- **无代码执行**：全部是 Markdown 文本，不含脚本、不含可执行文件
- **无网络请求**：skill 本身不联网、不上报、不采集数据
- **已脱敏**：仓库内不含真实系统用户名、真实个人绝对路径、城市等可识别信息 —— 文中示例路径统一写作 `C:\Users\<用户名>\...`
- **已排除密钥类文件**：`.gitignore` 预置了 `.env`、`*.pem`、`*.key`、`id_rsa*`、`credentials.json`、`*.db` 等规则，防止后续误提交
- **使用提醒**：`references/identity.md` 中的「主人档案」记录了使用者偏好。若你 fork 本仓库并填入自己的信息，请先确认仓库可见性（建议 Private）
